# AEGIS — Attribution & Evidence Graph Intelligence

[![CI](https://github.com/meharkp7/DarkWeb_SIH26151/actions/workflows/ci.yml/badge.svg)](https://github.com/meharkp7/DarkWeb_SIH26151/actions/workflows/ci.yml)

Provenance-aware, temporal, multimodal intelligence for discovering and
*explaining* relationships among evolving threat personas. Models produce
hypotheses; analysts make findings.

> **Scope: synthetic-only.** AEGIS generates and evaluates against controlled
> synthetic data. It does not collect from, or operate against, live targets.
> Every record in the ledger, every graph, every "actor" is generated by
> `scripts/seed_demo_data.py`.

## Quick start

```bash
cp .env.example .env          # then set AEGIS_AUTH_* to the values above
uv sync --extra dev
make infra-up                 # docker compose: Postgres 17 + OpenSearch 2.19
make migrate                  # alembic upgrade head
make demo-reset               # ~4.3k evidence records, 7 cases (add --index for search)
make run                      # API on :8000
make frontend-dev             # console on :5173
```

No `uv`? `curl -LsSf https://astral.sh/uv/install.sh | sh`, restart the
terminal, re-run.

**OpenSearch is optional.** `make infra-up` is a convenience, not a
requirement. Without it, the copilot falls back to a PostgreSQL-backed search
engine over the same `evidence` table and says so in every answer; the global
search box is pure SQL and never needed it. The deployment does exactly this —
see [Deployment](#deployment).

> **After seeding, pass `--index` if you started OpenSearch.** Without it the
> index is left holding a previous dataset and every search silently returns
> nothing. There is no error for this anywhere, which is a real papercut:
> `make demo-reset` does not pass it.

## Architecture

### The one rule

```
Evidence → Provenance → Graph → Baselines → Multimodal features
        → Temporal modeling → Contradiction fusion → GNN
        → Adversarial benchmark → UI → Hardening
```

Never: `LLM → guess → graph → dashboard`. A model may propose a link; only
cited evidence may assert one, and an analyst decides.

### Storage

**PostgreSQL is the system of record.** Its schema comes *only* from
`alembic/versions` — run `make migrate`, never ad-hoc DDL. Everything else is
a non-authoritative adapter imported lazily behind an optional extra, and the
in-process implementation is what tests and CI run:

| Concern | Authoritative | Adapter (optional) | In-process default |
|---|---|---|---|
| Evidence, provenance, audit | PostgreSQL | — | — |
| Retrieval | same `evidence` table | OpenSearch | `aegis.search.engine` |
| Relationships | PostgreSQL | Neo4j | `aegis.graph` |
| Objects | PostgreSQL metadata | S3-compatible | `aegis.storage` |
| Models | torch (the `ml` extra) | — | numpy baselines |

This is why the free-tier deploy works at all: the two services that would
have been the hard part are the ones that are optional.

### Request path

```
Console (Vercel)  ──HTTPS+WSS──►  API (FastAPI + WS)  ──SQL──►  Postgres (Supabase)
      │                                │
      │  every URL via apiUrl()        ├─ in-process graph, numpy baselines
      │  (never a literal /api path)   ├─ search: OpenSearch, else Postgres fallback
      └─ copilot: deterministic intent routing, cited claims only
```

### Trust boundaries

- **Everything retrieved is untrusted data.** The copilot wraps it in a
  delimiter region, never executes it, and quarantines any record matching an
  injection indicator from the claims it may support. The verdict is shown in
  the UI, not swallowed.
- **Every mutation is audited in the same transaction** as the change itself,
  so a rollback discards both. The chain is hash-linked, and
  `GET /api/v1/admin/audit/verify` proves it.
- **No model output is ever a finding.** Hypotheses are records with evidence
  links; assessments carry a calibrated confidence or none at all.

## The console

| Route | What it is |
|---|---|
| `/` | Command Center — posture counts, evidence velocity, attribution posture, live activity |
| `/cases` · `/cases/:caseId` | Investigations; the workspace is graph, hypotheses, timeline, signals, assessment, evidence |
| `/actors` · `/actors/:actorId` | The actor registry and the trust graph between actors |
| `/infrastructure` | Correlate clearnet and onion observations into findings; findings, matches, observations |
| `/personas` | Persona linkage and adjudication |
| `/collection` | Collector orchestration, sources, run history |
| `/threat-watch` | Live event stream; select an event for the full recorded payload |
| `/admin` | Team, audit chain verification, adapter health |

The agent (`⌘J`) is available on every screen. It is a **deterministic**
copilot — intent routing, retrieval, citation validation, containment. There
is no LLM in the answer path, so an answer is reproducible and every sentence
in it traces to a record.

```bash
make security-scan # dependency + secret scan

```

| Gate | Current |
|---|---|
| Backend tests | **822 passing** (+124 integration, gated on a live Postgres) |
| Frontend tests | **196 passing** (19 files) |
| Browser E2E | 8 Playwright specs + an axe accessibility audit |
| Integration suite | **937 passing** against a real Postgres 17 |
| mypy | strict, 163 modules |
| TypeScript | strict, both app and build config |

### CI

Eight jobs, all required:

| Job | What it does |
|---|---|
| Backend | lint, typecheck, tests with `--extra ml` |
| Migrations | empty database → `head`, then a drift check |
| Integration | migrations + seed, then pytest against a **real Postgres 17** with `AEGIS_REQUIRE_DB=1` |
| Frontend | typecheck, lint, test, build |
| Deploy config | `render.yaml` / `vercel.json` parse |
| Schema validation | canonical schemas + ontology |
| Package build | `uv build` + wheel import check |
| Security | dependency scan, secret scan, security tests |

`AEGIS_REQUIRE_DB=1` turns "PostgreSQL unreachable" from a skip into a
failure, so a wiring mistake cannot quietly reduce a run to nothing.

The `ml` extra (torch, xgboost, scikit-learn — ~2GB) is installed only in the
`backend` job. Tests needing it skip elsewhere rather than fail, so the
integration job stays fast without losing coverage.

## Configuration

| Variable | Purpose |
|---|---|
| `AEGIS_DATABASE_URL` | PostgreSQL DSN. Required; the audit chain uses advisory locks. |
| `AEGIS_AUTH_EMAIL` / `_PASSWORD` / `_SECRET` | The single configured analyst, and the token HMAC key. |
| `AEGIS_AUTH_DISPLAY_NAME` / `_ROLE` / `_ORGANIZATION` | Shown in the console header. |
| `AEGIS_OPENSEARCH_URL` | Optional. Absent ⇒ PostgreSQL search fallback. |
| `AEGIS_CORS_ORIGINS` | Explicit allowlist. A wildcard with credentials is rejected. |

### Extras

The ML stack is **optional by design** — on a free-tier host the build is what
fails, and none of the analytics that matter (command center, actors,
infrastructure, personas, collection, temporal) touch it.

| Extra | Provides | Enables |
|---|---|---|
| `dev` | pytest, mypy, ruff, httpx | everything below works without it, but you get no checks |
| `search` | `opensearch-py` | `OpenSearchAdapter` |
| `s3` | `boto3` | `S3ObjectStore` |
| `ml` | torch, xgboost, scikit-learn | learned baselines, GNN training |
| `report` | `reportlab` | PDF report export |
| `telemetry` | `opentelemetry-api` | tracing |

```bash
uv sync --extra dev --extra search --extra s3
```

## Deployment

Free tier, three services, documented in [`DEPLOY.md`](DEPLOY.md):

| | |
|---|---|
| **Supabase** | managed PostgreSQL |
| **Render** | FastAPI + websocket |
| **Vercel** | the built console |

Two free-tier behaviours to know before a walkthrough:

- **Render sleeps after ~15 min idle.** The console degrades correctly — it
  falls back to REST and the sidebar says "Reconnecting" — but the first
  request after a sleep takes ~30s.
- **OpenSearch and Neo4j are not deployed**, and do not need to be. Search
  falls back to PostgreSQL; the graph uses the in-process store.
  Administration reports both as "unavailable", which is advisory rather than
  an outage.

The console and the API are on different origins by design, so every request
goes through `apiUrl()`. `tests/test_package_imports.py` and
`apps/frontend/src/api/apiBase.test.ts` fail the build if a literal `/api`
path reappears — that class of bug is invisible in local dev and fatal in
production.

## What is real, and what is not

Stated plainly, because the gap is easy to guess wrong.

**Real and exercised by tests:** the evidence ledger and its hash-chained
audit, the schemas and ontology, entity resolution across five baselines,
the temporal graph and change detection, infrastructure correlation, persona
linkage, the actor registry and trust graph, collection orchestration, search
and retrieval, the citation-validating copilot, and the console.

**Deliberately synthetic:** every actor, handle, wallet, marketplace and
network. There is no collector pointed at a real target and no ingestion path
that accepts one.

**Known-incomplete:**

- **Ingestion is synthetic-only.** `POST /api/v1/evidence` accepts a record,
  but nothing in this repository collects from a live source.
- **The copilot is not an LLM.** It routes, retrieves, validates and
  synthesizes deterministically. It will not answer a question the rule table
  does not recognise, and it says so rather than guessing.
- **`generate_report` produces a brief, not a narrative.** It groups the
  answer's validated claims by the tool that produced them. There is no
  prose model behind it.
- **The copilot holds one exchange at a time** — a second question replaces
  the first. There is no conversation history yet.
- **Optional adapters are thin.** OpenSearch, Neo4j and S3 are exercised
  against their contracts, not at scale.
